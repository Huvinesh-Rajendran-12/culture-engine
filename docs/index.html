Culture Engine

An agent runner built like a ship's mind.

Culture Engine runs agent sessions as supervised OTP processes — each one a GenServer with its own conversation history, able to spawn drones for subtasks, write new tools for itself at runtime, and report back through a live Phoenix observatory. It borrows its vocabulary — Minds, drones, ship names — from Iain M. Banks' Culture novels, because that's roughly the shape multi-agent orchestration wants: a supervised hierarchy of minds, not a script.

Architecture

Supervision tree

Everything hangs off one OTP supervisor. Agents are discovered by registry, not by reference — any process can find any agent by ID.

AgentHarness.Supervisor
├─ Registry (AgentRegistry)        — agent discovery by ID
├─ DynamicSupervisor (AgentSupervisor)  — manages agent processes
├─ ToolRegistry                   — singleton built-in tool registry
├─ Phoenix.PubSub (PubSub)        — event broadcasting
└─ Endpoint                       — Phoenix HTTP, port 4000

Agent loop

What happens on a turn

chat(pid, message) drives a loop that keeps calling the model until it stops asking for tools.

  1. Build the tool list

    Filtered by the agent's nesting depth and tier — a drone at max depth sees a smaller toolset than a Mind.

  2. Call the model

    API.chat/3 sends the conversation to Anthropic or OpenRouter, whichever key is configured — OpenRouter wins if both are set.

  3. Handle the response

    Tool-use blocks get executed and their results appended, then the loop repeats. Text-only replies end the turn.

  4. Route the special tools

    spawn_agent creates a drone GenServer (sync or async); create_tool registers a brand-new tool directly into that agent's own ToolSet.

Multi-agent system

Minds and drones

Every session starts with one Mind. The Mind can spawn drones for subtasks, and — up to a point — drones can spawn drones of their own.

Mind

Top-level agent. The only tier that can define new tools with create_tool.

e.g. "Considering the Alternative"

Drone

Spawned for a subtask. Runs sync (parent blocks, gets the result as tool output) or async (reports back via drone_complete).

e.g. "Quietly Considering Ambiguity"

Depth limit
Drones can spawn sub-drones up to depth 3. At max depth, an agent loses spawn_agent.
Identity
Each agent gets a short UUID and a Culture-style ship name, and registers itself in AgentRegistry.
Tool isolation
Each agent owns its own ETS table via ToolSet — dynamic tools never leak between agents.

Sandbox

Tool safety

  • run_command executes in an isolated environment with a 30-second timeout and a 50KB output cap.
  • Dynamic tools are shebang scripts under the same sandbox constraints, capped at 10 per agent.
  • Filesystem search prefers rg for content and fd for file discovery.
